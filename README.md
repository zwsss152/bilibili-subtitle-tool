# 文字稿 · B 站、抖音与机核

Windows 本地工具，Python 3.13 + Tkinter。B 站优先提取中文字幕，没有字幕时走音频识别；机核使用官方音频；抖音视频、分享短链和含 modal_id 的网页链接已接入音频识别流程。抖音当前真实样本受到访问限制，尚未通过下载到转写的完整验收；遇到限制会明确报错。

## 启动与使用

当前电脑已配置独立 `.venv`、GPU 依赖和模型，双击 **启动.bat** 或 **批量转写.bat**，两个入口均打开同一个应用。启动失败时运行 **环境诊断.bat**，详细原因保存在 `logs/app.log`。

1. 粘贴 B 站视频、BV / av 号、b23.tv 短链、抖音分享／视频链接或机核电台 `/radios/编号` 链接，可一次粘贴多个。
2. 在归档主题框输入名称，点“创建主题”建立文件夹；下拉选择已创建的主题，再加入队列。入队时主题与输出目录固定，随后切换主题只影响新任务。
3. 选择队列任务或右侧已有稿件，阅读带时间戳、通读或原始记录；稿件列表展开时自动更新，任务完成后也会自动更新。
4. 在稿件中选中文字，点“复制选段”；蓝色“复制全文”按钮复制当前视图。

普通 B 站视频链接处理全部分 P；`?p=2` 只处理 P2。左侧可拖动分隔条调整队列与阅读区比例。设置中的 B 站 Cookie 用于字幕和音频请求，仅保存在本项目配置中。部分字幕需要登录 Cookie，画面上的硬字幕由音频识别处理。

暂停停止派发新阶段，当前下载或识别阶段会完成。删除取消后台任务并同步删除该任务对应的 TXT 与内部识别记录，不删除其他任务的稿件或主题文件夹。文件被占用等删除失败时保留记录并显示原因。重试只重排失败分 P；重新启动恢复未完成部分。关闭窗口保存队列并结束识别进程，未完成音频可重新下载。“打开文件夹”打开当前稿件或归档主题所在目录。

## 输出与数据

- `文字稿/主题/*.txt`：简体分段稿，含来源和时间戳。
- `.data/transcripts/`：程序内部的逐条识别记录，保留时间与实际模型信息。主题文件夹只生成 TXT；旧的同名 JSON 会在启动时自动迁到内部目录。
- `queue_state.json`：逐任务、逐分 P 状态，串行写入并原子替换；损坏记录备份后恢复有效任务。
- `app_config.json`：主题、窗口尺寸、Cookie；不纳入 Git。
- `models/`：识别与标点模型；`asr_cache/`：按任务归属的音频，完成、取消和退出后清理。
- `logs/`：启动及运行诊断；正常流程的识别在本机进行。平台获取与首次模型下载需要联网。

旧目录保持原状。已迁入 Git 历史、旧工作区源码、7 份历史稿件、配置、队列和已有模型。GitHub 版本包含源码、测试和验收说明；本机稿件、配置、队列、模型与完整识别验收稿不入库。

## 识别档位与质量

一个常驻识别工作进程，最多两份音频预下载。默认 large-v3-turbo / CUDA FP16 / beam 5 / batch 8，随后自动用本机 SenseVoice int8 复核中文语音。无需填写词表或选择模型。仅采用与原读音一致的短字词修正，不引入复核中的额外重复、语气词或句子改写。两次解码均保存在原始 JSON 中，时间戳沿用首轮；复核若为空、长度异常、数字冲突或内容差异过大，保留首轮。复核模型自动下载，加载失败时保留 Whisper 结果并记录原因。显存不足逐级缩小批次，GPU 失败回退 CPU，记录实际设备。

保留原话及有意重复，不删重复数字。文字处理仅做繁简转换、标点和分段；标点模型若改变文字或数字顺序，保留原文并记录原因。未加入摘要、改写、说话人识别和翻译。

本机已测六段固定两分钟样本，并使用用户报告出错的原视频测试新版自动复核：原“捋了个油”改为音频对应的“旅了个游”，没有设置硬编码替换规则。按用户最新要求改用自动中文复核方案；这项实测不代表全文零错误，六段样本的完整人工 CER 验收仍未完成。实测数据与验收限制见 [验收记录](docs/validation.md)。

`benchmarks/` 保留开发验收的样本和模型对照，不是日常使用步骤；用户只需粘贴链接。音频、完整识别稿及任务记录只在验收电脑保存；仓库仅提供测量统计和公开样本信息。性能及准确度记录不把机器输出当作人工参考答案。

## 复现环境与开发

新电脑安装 Windows 64 位 Python 3.13 后运行 **安装环境.bat**。完整版本锁定在 `requirements.lock.txt`，直接依赖列于 `requirements.txt`。GPU 使用已验证的 pip CUDA/cuDNN 运行库，无需安装 PyTorch；驱动须支持对应 CUDA。PyAV 固定 18.1.0，19.0.0 与当前 faster-whisper 解码接口不兼容。

```powershell
.venv\Scripts\python.exe -B -m unittest discover -s tests -v
.venv\Scripts\python.exe -B -m src.diagnostics
.venv\Scripts\python.exe -B tools/benchmark.py
```

源码职责：`src/ui` 仅界面与事件消费；`src/services` 管理任务、持久化与识别进程；`src/core` 分为平台接口、链接解析、下载、模型、识别和文字处理；`src/main.py` 是唯一入口。后台服务不读取 Tk 变量，也不操作控件。

批处理使用方式与 GPU 依赖参考 [faster-whisper 官方项目](https://github.com/SYSTRAN/faster-whisper)，标点模型来自 [sherpa-onnx 官方中文/英文 CT-Transformer int8 模型](https://k2-fsa.github.io/sherpa/onnx/punctuation/pretrained_models.html)。速度结论仅依据本机实测。

中文复核使用 [sherpa-onnx 官方 SenseVoice 模型及接口](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)，在 CPU 运行，与常驻 GPU 识别模型分工。

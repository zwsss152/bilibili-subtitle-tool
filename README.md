# 文字稿 · B 站、抖音、机核与本地媒体

Windows 桌面工具，Python 3.13 + Tkinter。保留本地识别与整理，另可切换阿里云百炼在线方式，初始默认本地。本地 B 站保留人工中文字幕优先，自动字幕转音频识别；在线任务直接识别音频。机核使用官方音频；抖音直接访问失败时自动使用专用 WebView2 会话，已通过一条约九分钟公开视频的真实双稿件流程。

## 启动与使用

当前电脑已配置独立 `.venv`、GPU 依赖和模型，双击 **启动.bat** 或 **批量转写.bat**，两个入口均打开同一个应用。启动失败时运行 **环境诊断.bat**，详细原因保存在 `logs/app.log`。

顶部只有“本地／在线”方式切换，同时影响新任务的识别和阅读稿整理。每个任务入队后固定方式，切换不会改变已入队任务；本地失败不会自动上传。在线方式首次在已有“设置”窗口输入北京地域的百炼 API Key，留空保存会保留现有密钥。

1. 粘贴 B 站视频、BV / av 号、b23.tv 短链、抖音分享／视频链接或机核电台 `/radios/编号` 链接，可一次粘贴多个。
   已下载的视频或音频可点“选择文件”多选，选好后直接加入当前主题与识别方式的队列；也可以粘贴完整文件路径（支持“复制文件地址”产生的双引号）。支持 MP4、MKV、MOV、WEBM、AVI、MP3、WAV、M4A 等常见格式。程序只读取原文件，不复制整部视频、不修改或删除原文件；文件移动后任务明确报错，恢复到原位置再点重试。没有音轨、空文件或损坏媒体无法转录。
2. 在归档主题框输入名称，点“创建主题”建立文件夹；下拉选择已创建的主题，再加入队列。入队时主题与输出目录固定，随后切换主题只影响新任务。
3. 新任务只生成“时间戳原稿”。选中稿件后，点击版本下拉框旁的“整理”按钮，才生成当前篇的“整理阅读稿”；不会同时整理其他稿件。下拉切换两个版本，列表每篇只显示一次。整理中显示进度，完成后可阅读；已有阅读稿保留。
4. 在稿件中选中文字，点“复制选段”；蓝色“复制全文”按钮复制当前视图。
5. 在处理队列中右击已完成的任务，选择“重命名稿件”，输入名称后按 Enter 或点保存；Esc 取消。两份 TXT、队列、稿件标题和内部关联同步更新，多分 P 保留 `_P1` 等编号。任意一边同名冲突都不会覆盖，失败整体回滚。

阅读区按文章排版：微软雅黑 13 磅正文、清晰的小标题、灰色来源信息与柔和蓝色时间戳；宽窗口限制正文行宽，窄窗口自动换行。`#`、`##` 标记只用于识别标题，不显示在阅读区。段落内部的换行合并，空行和章节边界保留；排版不会修改两类 TXT。复制全文包含当前版本完整标题、来源和正文。

普通 B 站视频链接处理全部分 P；`?p=2` 只处理 P2。左侧可拖动分隔条调整队列与阅读区比例。设置中的 B 站 Cookie 用于字幕和音频请求，仅保存在本项目配置中。部分字幕需要登录 Cookie，画面上的硬字幕由音频识别处理。

主题菜单以“时间戳原稿”下实际存在的主题目录为准。外部删除后菜单自动刷新，残留在“整理阅读稿”中的同名目录不会继续显示为归档主题；不会替你删除阅读稿。已完成原稿被外部删除时，重启标记为失败，只有明确点击重试才重新生成。

抖音浏览器访问复用本机已有的 Microsoft WebView2，不读取日常浏览器的 Cookie。正常获取播放信息时不弹窗；15 秒内未取得时显示访问窗口，若平台要求登录或验证，请自行完成，工具会继续处理。关闭访问窗口保留任务，可重试；等待上限为五分钟。不支持私密、已删除视频或图集，不保证所有公开视频均可访问。

暂停停止派发新阶段，当前下载、识别或整理分块会完成。删除取消后台任务并同步删除两份 TXT 与内部识别记录，不删除其他任务的稿件或主题文件夹。文件被占用等删除失败时保留记录并显示原因。重试只重排失败分 P 和失败的整理；重新启动恢复未完成部分。关闭窗口保存进度并结束识别、整理进程，未完成音频可重新下载。“打开文件夹”打开当前版本的主题目录。

## 输出与数据

- `文字稿/时间戳原稿/主题/*.txt`：含来源和时间戳的完整原稿，整理不会改动它。
- `文字稿/整理阅读稿/主题/*.txt`：相同文件名的阅读稿，含来源、小标题、自然段和整理方式。创建主题同时建立两个目录；旧稿件在启动时自动迁移，原文件名和字节保持不变。
- `.data/transcripts/`：程序内部的逐条识别记录，保留时间与实际模型信息。主题文件夹只生成 TXT；旧的同名 JSON 会在启动时自动迁到内部目录。
- `queue_state.json`：逐任务、逐分 P 状态，串行写入并原子替换；损坏记录备份后恢复有效任务。
- `app_config.json`：主题、窗口尺寸、Cookie；不纳入 Git。
- `.data/cloud-key.dpapi`：Windows 本机加密的 API Key；在线分块进度与用量也放在 `.data/`，不进入稿件、日志或 Git。在线仅发送音频、标题／简介上下文和待整理文字，不发送平台 Cookie。
- `.data/douyin-browser/`：仅供本工具的抖音浏览器会话，由 WebView2 管理，可能含登录状态，不进入 Git 或输出目录；播放地址仅在后台内存使用。取消、删除或退出会请求结束访问进程。
- `models/`：识别与标点模型；`asr_cache/`：按任务归属的音频，完成、取消和退出后清理。
- `models/reading-editor/`：本地 Qwen3-8B Q4_K_M；`.data/runtime/`：固定版本 llama.cpp CUDA；`.data/library-migration/`：迁移事务及备份。完整模型约 5.03GB，运行环境也只安装在项目内。
- `logs/`：循环保存启动及运行诊断。本地方式在本机识别与整理；在线方式发送音频和文字到百炼。平台获取需要联网。
  本地文件同样遵循当前方式：选择“在线”会把音频分块发送给百炼；选择“本地”在本机识别。生成原稿后仍需点击“整理”才生成阅读稿。“打开来源”用系统播放器打开原视频或音频。删除队列任务只删输出稿件与内部记录，原文件不受影响。

旧目录保持原状。已迁入 Git 历史、旧工作区源码、7 份历史稿件、配置、队列和已有模型。GitHub 版本包含源码、测试和验收说明；本机稿件、配置、队列、模型与完整识别验收稿不入库。

## 识别档位与质量

一个识别工作进程，最多两份音频预下载。本地默认 large-v3-turbo / CUDA FP16 / beam 5 / batch 8，再用 CPU SenseVoice int8 独立解码。已撤掉干扰转写的通用提示和重复惩罚；对异常字符、严重漏句按实际声学结果恢复，保留两份解码及原因。普通同音字修正更加克制，不盲目采用孤立单字差异。数字冲突、内容无法对应时保留首轮；异常字符仍存在时任务失败，不把坏结果判成功。显存不足缩小批次，GPU 失败回退 CPU。

在线使用 `qwen-audio-3.0-asr-flash`，两分钟音频分块直传，核对实际 PCM 字节数并生成明确尺寸的 WAV，获取非流式最终 JSON；用量时长不作为完整处理游标。邻接保留两秒重叠并按词时间归属；缺少完整词时间戳则重取无重叠范围，记录真实分块时间。分块成功后原子保存，断网、限流、欠费或鉴权失败保留已完成部分。原稿保存后，点击“整理”才由 `qwen3.5-plus` 写当前篇的完整书面稿，再由 `qwen3-max` 独立核对。在线切换不加载本地 GPU 模型。

时间戳原稿保留原话及有意重复，仅做繁简、标点和分段。阅读稿以完整书面表达为目标，保留事实、例子、条件、观点归属和顺序，减少无意义串场与重复起句；不生成摘要或补外部知识。数字、单位、英文和引语另做检查；模糊代词不猜姓名。每段保留原文、时间范围与检查原因，失败段落最多再整理一次，仍不合格则原文排版。在线鉴权等接口失败明确显示整理失败，不冒充已整理结果。

本地识别与整理串行切换 GPU 模型，新任务优先，分块进度可恢复。新版完整书面稿仍有较多保守回退，本地错词也未全部解决；自动检查不能证明零遗漏。新任务可使用两种方式，历史稿件暂不批量覆盖。实际数据、用量和未通过项见 [本地／在线验收](docs/dual-mode.md)，旧版数据见 [历史阅读稿验收](docs/reading-quality.md)。

本机已测六段固定两分钟样本，并使用用户报告出错的原视频测试新版自动复核：原“捋了个油”改为音频对应的“旅了个游”，没有设置硬编码替换规则。按用户最新要求改用自动中文复核方案；这项实测不代表全文零错误，六段样本的完整人工 CER 验收仍未完成。实测数据与验收限制见 [验收记录](docs/validation.md)。

`benchmarks/` 保留开发验收的样本和模型对照，不是日常使用步骤；用户只需粘贴链接。音频、完整识别稿及任务记录只在验收电脑保存；仓库仅提供测量统计和公开样本信息。性能及准确度记录不把机器输出当作人工参考答案。

## 复现环境与开发

新电脑安装 Windows 64 位 Python 3.13 后运行 **安装环境.bat**。完整版本锁定在 `requirements.lock.txt`，直接依赖列于 `requirements.txt`。GPU 使用已验证的 pip CUDA/cuDNN 运行库，无需安装 PyTorch；驱动须支持对应 CUDA。PyAV 固定 18.1.0，19.0.0 与当前 faster-whisper 解码接口不兼容。

```powershell
.venv\Scripts\python.exe -B -m unittest discover -s tests -v
.venv\Scripts\python.exe -B -m src.diagnostics
.venv\Scripts\python.exe -X utf8 -B tools/benchmark_dual.py --engine local --run local-check --write
.venv\Scripts\python.exe tools/setup_reading.py
.venv\Scripts\python.exe -X utf8 -B tools/reading_pipeline_qa.py --engine local --run pipeline-check
```

源码职责：`src/ui` 仅界面与事件消费；`src/services` 管理任务、持久化与识别进程；`src/core` 分为平台接口、链接解析、下载、模型、识别和文字处理；`src/main.py` 是唯一入口。后台服务不读取 Tk 变量，也不操作控件。

批处理使用方式与 GPU 依赖参考 [faster-whisper 官方项目](https://github.com/SYSTRAN/faster-whisper)，标点模型来自 [sherpa-onnx 官方中文/英文 CT-Transformer int8 模型](https://k2-fsa.github.io/sherpa/onnx/punctuation/pretrained_models.html)。速度结论仅依据本机实测。

中文复核使用 [sherpa-onnx 官方 SenseVoice 模型及接口](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)，在 CPU 运行，与常驻 GPU 识别模型分工。

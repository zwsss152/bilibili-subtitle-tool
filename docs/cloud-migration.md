# 云端迁移与项目优化评估

本次保留 Windows / Tkinter 桌面端，识别和整理全部调用阿里云百炼。没有部署网站，也没有把平台 Cookie 发送给模型服务。

## 项目现状与处理流程

这是一个以稿件归档和阅读为中心的视频转录工具，而不只是下载字幕的脚本：

1. `core/links.py` 解析 B 站、抖音、机核和本地文件。
2. `services/scheduler.py` 解析内容、最多预取两份音频、派发识别工作进程。
3. `core/cloud.py` 提取两分钟音频块，经 HTTPS 调用百炼，保存断点、用量和识别时间。
4. `core/textout.py` 保存时间戳原稿；原始识别记录进入 `.data/transcripts/`。
5. 用户点击“整理”后，`reading_service.py` 分块生成阅读稿，进行独立信息核对。
6. Tkinter 界面提供主题归档、阅读、复制、重试和事务式重命名。

值得保留的基础：UI 与后台服务分离、原稿和阅读稿分离、原子持久化、任务拥有的缓存清理、重命名回滚、分块续作，以及不在日志里输出密钥和接口响应正文的设计。

## 本次落地

- 默认及新建任务固定为 `cloud`，移除方式切换和标点模型下载入口。
- 删除 Whisper / SenseVoice 推理、本地模型管理、llama.cpp / Qwen 本地整理代码及对应安装、评测工具。
- 从依赖中移除 faster-whisper、CTranslate2、sherpa-onnx、ONNX、CUDA/cuDNN、Hugging Face 等本地模型依赖。
- 保留 PyAV 和 FFmpeg，用于媒体检查、音频转换；保留 OpenCC 和纯文本检查。这些不会运行本地 AI 模型。
- 不再创建 `models/`。旧环境已有的模型和虚拟环境不自动删除，避免破坏现有安装；可在验证新版后手动清理。
- 旧配置即使保存了 `engine=local`，界面也统一使用云端。没有 API Key 时，入队和手动整理都会提前拦截。
- 旧本地未完成任务标为可重试；用户点击重试且已配置密钥后，只把未完成部分转为云端。已完成原稿保留。旧本地整理请求不会因启动新版自动上传。
- 已完成且源文未变化的阅读稿保留，包括旧整理版本；云端接口失败明确标记“整理失败”，保留原稿和已保存分块。
- 保留 API Key 的 Windows DPAPI 加密、断点、限流重试、取消和退出清理。

当前云端模型沿用原项目：`qwen-audio-3.0-asr-flash` 识别、`qwen3.5-plus` 整理、`qwen3-max` 核对。未擅自切换模型或触发付费请求。

## 后续优化建议

| 优先级 | 代码依据与问题 | 建议及验收方式 |
| --- | --- | --- |
| P0 | `cloud.py` 支持分块续作，但依赖固定地域、固定模型和实际账户权限 | 设置页增加“连接测试”，分别检查识别、整理、核对权限；将模型配置纳入断点指纹；错误区分密钥、余额、限流和模型不可用。连接测试应明确是否产生费用。 |
| P0 | 在线计费与 `qwen3-max` 独立核对已有用量记录，但界面缺少完整成本反馈 | 显示待处理音频分钟数、实际用量、请求次数，提供用户设置的单任务时长和批量预算上限；价格必须可更新，估算不冒充最终账单。 |
| P1 | 旧本地分支曾优先获取人工 CC，现有在线路径始终识别音频 | 增加“优先使用人工字幕”选项，复用平台字幕接口；无可靠字幕才调用云端。保存来源和字幕类型，自动字幕作为可选策略，避免误称人工稿。 |
| P1 | 云端请求同步占用串行调度，音频和阅读稿互相等待 | 在可靠续作基础上拆成有界识别队列和整理队列；按账户配额控制并发，加入抖动退避，验证暂停、取消、限流时无重复派发。先测端到端耗时再决定并发数。 |
| P1 | `batch_app.py` 集中承担界面、设置、队列操作和稿件读取；`scheduler.py` 同时承担多阶段生命周期 | 将设置、队列视图、阅读控制器拆开，调度器拆成下载、识别、持久化协作组件；保留现有事件契约和事务测试，避免一次重写。 |
| P1 | 队列整体写入 JSON；稿件与内部记录跨多个文件 | 任务量扩大后迁移到 SQLite：任务、分 P、状态变更和用量事务写入，TXT 继续作为用户导出；提供迁移备份和幂等恢复，先基准测试再实施。 |
| P2 | 仓库有较多本机历史验收文档与截图，缺少自动运行的 CI 工作流 | Windows CI 执行无付费请求的单元测试、依赖完整性检查和 UI 冒烟测试；真实云端验收手动运行并限制音频时长。发布版本标记模型、地域、依赖及验证范围。 |
| P2 | 阅读稿已有信息核对，但自动检查不能证明零遗漏 | 固定小规模人工标注样本，覆盖数字、专名、多说话人、长静音和分块边界；同时报告漏句率、数字错误、回退比例、时延和费用，不能仅用模型自评判定准确率。 |

建议先做连接测试、用量展示和人工字幕复用，再考虑并发及 SQLite。先提高使用可预测性，随后按真实任务量调整架构。

## 使用与迁移

1. 在新的目录安装依赖并启动；不需要显卡或模型下载。
2. 在设置中填写北京地域百炼 API Key，可选填业务空间 ID；也支持 `DASHSCOPE_API_KEY` 环境变量。
3. 升级现有目录前备份 `文字稿/`、`.data/`、`queue_state.json`、`app_config.json`。DPAPI 密钥绑定 Windows 用户及机器，换机需重新填写。
4. 保留上述数据文件；旧本地未完成任务明确点击重试才上传。已有原稿可选中后单独点击“整理”。
5. 旧虚拟环境可能仍保留 GPU 包。要获得轻量安装，应在新目录安装依赖，而不是只覆盖源码。

音频、标题/简介与待整理文字会发送到百炼，并可能产生服务费用；本地原视频不会整份上传。平台访问与 Cookie 仍在桌面端处理。

## 验证范围

完整单元测试使用模拟 HTTP / 模拟整理器，不调用真实收费模型；覆盖云端响应、音频边界、断点、取消、队列恢复、本地文件、稿件读写、重命名回滚及迁移保护。测试记录见 `cloud-validation.md`。

尚未验证：真实 API Key 的账户权限和余额、真实云端端到端质量/费用、不同机器显示缩放下的完整 UI 验收。历史验收材料只描述当时版本，不能用作本版真实模型验收结论。

官方接口依据：

- [语音识别模型与单次输入限制](https://help.aliyun.com/en/model-studio/asr-model)：当前两分钟 PCM/WAV 分块延续原项目设计，避免整段长音频超限。
- [Qwen3.5-Plus](https://help.aliyun.com/en/model-studio/qwen3-5-plus)：云端整理模型说明。
